# 设计稿到可运行代码

## 识别输入

先核对目标工程、技术栈、路由、现有组件、设计变量和可用资产。拆出页面结构、可复用部件、文字与数据、交互、状态、响应式行为；区分参考图、实际设计稿和已授权素材。图像生成的文字、数值、图标、图表可能失真，业务内容另行核实。

## 实现

1. 明确工作范围与文件清单，在现有工程内增量实现。概念图只作视觉基准；需要保留的装饰元素单独提取或重建，并记录来源及授权。
2. 用真实 DOM/组件实现标题、列表、表单、导航和反馈；用合适的图表库实现数据图形。需要空间交互时再用地图或 3D，并核素材、许可与性能。不要用整张截图、裁出的图标或假图表伪装成可编辑页面。
3. 建立设计变量和组件状态，打通页面的点击、键盘、筛选、保存、返回、错误与空状态。对 mock 数据和未接通接口明确标记，不编造功能完成度。
4. 在设计稿和代码之间往返时，记录哪一边是当前准稿；同步变量、尺寸、文本与组件行为。导入 Figma 后检查 Auto Layout、可编辑性及变量绑定，不能只看预览相似。

## 验收

运行构建与必要测试，打开实际页面截图逐区对照：结构、比例、字体、留白、颜色、素材、滚动、遮挡。再走关键交互，检查不同视口和状态。3D/视频还需验证加载失败、暂停恢复和资源释放。交付改动文件、可运行入口、视觉差异及未验证项；不要用“一比一”描述尚未核对的效果。
